# 大模型对话 Chat

## 一、功能概述

本功能是整个客户端的核心基线：对接大模型 API，实现最基础的问答对话能力。

用户在输入框发送消息后，客户端将当前会话上下文一并提交给大模型，并以流式方式实时渲染模型回复。整个交互保持最小可用形态，不包含多余功能，为后续的会话历史、工具调用等能力提供基础。

## 二、通用大模型接入

客户端不绑定任何特定厂商，按“通用 API”思路设计，支持两类主流协议：

### 1. OpenAI 兼容协议

- 请求格式兼容 OpenAI Chat Completions 标准。
- 支持 OpenAI 官方 API，以及所有兼容该协议的国内/第三方服务（如 Kimi、Moonshot、DeepSeek、通义、OpenRouter 等）。
- 请求地址指向服务的 base URL，客户端自动拼接 `/chat/completions` 端点。
- 流式响应按 SSE 格式解析 `data: ` 行，提取 `choices[0].delta.content` 逐段输出。

### 2. Anthropic 协议

- 支持 Anthropic（Claude）原生 Messages API。
- 请求头使用 `x-api-key` 认证，并携带 `anthropic-version: 2023-06-01`。
- 请求地址指向服务 base URL，客户端自动拼接 `/v1/messages` 端点。
- 流式响应按 SSE 格式解析 `content_block_delta` 事件，提取 `delta.text` 逐段输出。

### 3. 协议适配层

- 两种协议的差异收敛在 Electron 主进程的协议适配模块（`electron/protocol.ts`）中。
- 对外暴露统一的调用接口，内部完成消息格式转换、端点拼接、请求头构造和响应流解析。
- 新增其他协议时，只需在适配层增加对应实现，前端和对话逻辑无需改动。

## 三、设置项

点击右上角“设置”按钮打开配置面板，包含以下字段：

| 字段 | 说明 | 默认值 |
|------|------|--------|
| 接口密钥 | 服务商颁发的 API Key | 空 |
| 协议 | `openai` 或 `anthropic` | `openai` |
| API 请求地址 | 服务 base URL，不含具体端点 | `https://api.kimi.com/coding/v1` |
| 选用模型 | 要调用的模型 ID | `kimi-code-plan` |

补充说明：

- 模型输入框带常用模型建议列表，也可手动输入任意模型 ID。
- 设置项保存在浏览器本地存储中，重启应用后保留。
- 接口密钥仅保存在本机，所有 API 请求都在 Electron 主进程发出，渲染进程不直接接触密钥。

### 检测联通

- 点击“检测联通”按钮，客户端会向服务发起一次连通性验证（OpenAI 协议请求 `/models`，Anthropic 协议请求一次最小化的 `/v1/messages`）。
- 成功时显示可用状态，失败时显示具体错误信息（HTTP 状态码或网络错误）。
- 若服务商未开放 `/models` 端点，检测可能失败，但对话接口仍可能可用。

## 四、对话交互

### 1. 发送消息

- 在底部输入框输入内容，按 `Enter` 发送，`Shift + Enter` 换行。
- 发送后用户消息立即出现在消息列表中，并插入一条空的助手消息用于承接流式输出。

### 2. 流式回复

- 模型输出以流式方式逐段渲染，无需等待完整响应。
- 收到数据流期间，输入框进入禁用状态，发送按钮变为“停止”按钮。

### 3. 停止生成

- 流式输出过程中点击“停止”按钮，客户端通过 `AbortController` 中断当前 HTTP 请求。
- 已接收到的部分内容会保留在消息中。

### 4. 上下文记忆

- 客户端将当前会话的全部消息作为上下文一并提交，模型可以引用前文回答追问。
- 上下文属于“临时记忆”：只在当前会话内生效。
- 点击“新对话”清空当前上下文；关闭应用后对话内容不保留。

### 5. 错误提示

- 请求失败时（HTTP 错误、网络异常、流解析异常），错误信息以 `[Error: ...]` 形式显示在助手消息中。
- 错误不会中断会话，修正配置或网络后可继续提问。

## 五、技术实现

### 1. 整体架构

- 渲染进程（React）只负责界面和状态管理。
- Electron 主进程负责全部网络请求，通过 IPC 与渲染进程通信。
- Preload 脚本以 `contextBridge` 方式暴露最小 API 面，避免渲染进程直接访问 Node 能力。

### 2. 消息流程

1. 渲染进程调用 `window.electronAPI.sendMessage`，携带配置、会话 ID 和消息列表。
2. 主进程按所选协议构造请求，发起流式调用。
3. 主进程解析 SSE 数据流，通过 `stream-chunk` 事件逐段推送给渲染进程。
4. 渲染进程将片段追加到最后一条助手消息上，形成流式渲染。
5. 流结束时发送 `stream-done`；异常时发送 `stream-error`。

### 3. 中断机制

- 每次发送生成唯一请求 ID，主进程用 `Map` 维护该 ID 与 `AbortController` 的对应关系。
- 渲染进程发送 `abort-message` 时按 ID 找到控制器并中断请求。

### 4. 关键文件

| 文件 | 职责 |
|------|------|
| `electron/main.ts` | 窗口创建、IPC 注册、API 请求代理、SSE 解析 |
| `electron/protocol.ts` | OpenAI / Anthropic 协议适配与消息格式转换 |
| `electron/preload.ts` | 暴露安全的 `window.electronAPI` |
| `src/hooks/useChat.ts` | 会话状态、发送、流式接收、中断 |
| `src/hooks/useApiConfig.ts` | 设置项读写与本地持久化 |
| `src/components/Chat.tsx` | 消息列表与输入框 |
| `src/components/Settings.tsx` | 设置面板与检测联通 |
| `shared/types.ts` | `ApiConfig`、`ApiProtocol` 等共享类型 |
| `shared/config.ts` | 默认配置与模型建议列表 |

## 六、隐私与安全

- API 密钥只保存在本机浏览器存储中，不上传、不外发。
- 所有模型请求由主进程直接发出，密钥不出现在渲染进程和前端源码运行时状态中。
- 对话内容仅保留在当前会话内存中，关闭应用即清空。

## 七、常见问题

### 1. 对话报 HTTP 400，提示参数不合法

部分模型对请求参数（如 `temperature`）有严格限制。客户端当前对话请求不附加额外采样参数，全部使用模型默认值；若仍报错，请确认模型 ID 与服务商要求一致。

### 2. 检测联通成功但对话失败

检测联通与对话调用走的是不同端点。可能原因包括：该 Key 无对话权限、所选模型不存在、账户额度不足等，请根据错误信息排查。

### 3. Anthropic 协议下地址该怎么填

填服务 base URL 即可（如 `https://api.anthropic.com`），客户端会自动拼接 `/v1/messages`；若地址本身已以 `/v1/messages` 结尾，则原样使用。

### 4. 切换协议后需要重新配置吗

接口密钥、请求地址、模型都是按协议独立生效的字段，切换协议后建议重新检测联通并保存设置。
