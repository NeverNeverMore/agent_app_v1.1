# 优化附件显示及拖拽功能

## 1. 功能概述

本次优化围绕附件上传后的可见性、图片预览持久化、权限选择器视觉以及文件拖拽上传体验展开：

- 用户消息中显示已发送的附件信息，避免附件发送后没有任何提示。
- 图片附件显示缩略图，Word、PDF、Excel、PPT 和文本文件显示文件图标、文件名与大小。
- 图片预览保存到 Electron 应用数据目录，重启应用后仍可以显示历史缩略图。
- “请求批准”权限选中态由橙红色调整为浅绿色。
- 支持从 Windows 文件资源管理器直接拖文件到主对话区域加入待发送附件。
- 拖拽过程中增加状态提示、数量限制反馈和诊断日志。

## 2. 附件消息展示

### 2.1 用户消息附件

发送消息时，用户消息会保存轻量附件元数据：

- 附件 ID
- 文件名
- 文件类型
- MIME 类型
- 文件大小
- 图片预览引用

不会把临时文件路径或非图片附件的完整解析文本写入会话历史。

### 2.2 图片附件

图片附件在消息下方以独立缩略图展示，不包在正文气泡内部。缩略图使用固定尺寸和等比例显示，避免大图片撑开对话布局。

图片预览文件保存于：

```text
C:\Users\<用户名>\AppData\Roaming\sifang-chat-client\attachment-previews\
```

实际路径通过 Electron 的 `app.getPath('userData')` 获取，不写入项目目录，也不写入用户选择的工作目录。

### 2.3 非图片附件

Word、PDF、Excel、PPT、文本等非图片文件不生成长期预览副本，只在消息中显示：

- 对应文件类型图标
- 文件名
- 文件大小

长文件名会截断显示，悬浮时可以查看完整名称。

## 3. 图片预览文件管理

### 3.1 文件生命周期

- 原始上传文件继续保存在系统临时目录，用于解析和发送。
- 原始临时附件按现有规则在发送后延迟清理，应用启动时也会清理过期目录。
- 图片预览文件只要仍被会话历史引用就保留。
- 删除会话或项目后，若图片不再被其他消息引用，则回收对应预览文件。

### 3.2 孤儿文件清理

应用会异步同步当前会话中仍被引用的图片预览 ID，并清理 `attachment-previews` 目录中不再被引用的文件。

清理过程只扫描固定预览目录和文件名，不读取全部图片内容，不阻塞主界面启动。预览文件缺失或读取失败时，历史消息仍保留文件名和附件信息，并显示文件占位卡片。

### 3.3 安全限制

- 预览文件名使用附件 UUID，不使用用户原始文件名。
- 渲染进程只能通过 Electron IPC 按附件 ID读取预览。
- 主进程会校验附件 ID和临时附件路径，避免读取任意本地文件。

## 4. 权限批准选择器

“请求批准”选中态调整为浅绿色视觉：

- 浅绿色背景
- 绿色主文字
- 绿色辅助说明
- 绿色勾选图标

“完全访问权限”保持原有语义和中性样式。批准失败、拒绝和错误状态颜色不随本次调整改变，避免与权限选择态混淆。

## 5. 文件拖拽上传

### 5.1 使用方式

从 Windows 文件资源管理器拖入本地文件到主对话区域：

1. 主内容区域显示“释放文件以上传”提示。
2. 在聊天区域释放文件。
3. 文件加入底部待发送附件列表。
4. 用户可以继续输入文字、移除附件或提交消息。

拖拽不会自动发送消息，也不支持拖入文件夹。

### 5.2 事件处理

拖放事件分为两层：

- `app-main` 使用原生捕获监听处理 `dragenter`、`dragover`、`dragleave` 和 `drop`，负责调用 `preventDefault()`、设置 `dropEffect = 'copy'` 并记录诊断日志。
- `Chat` 使用原生 `drop` 监听判断释放位置，只有释放到聊天区域时才真正导入附件。

主内容区域两侧的空白位置可以显示复制拖放状态，但释放在那里不会误加入附件。侧栏、设置区域和其他页面不参与附件导入。

### 5.3 文件路径兼容

拖入文件的本地路径按以下顺序获取：

1. Electron `webUtils.getPathForFile(file)`；
2. Electron 文件对象的 `path` 字段；
3. 两者都无法获取时显示明确错误。

诊断日志包括：

```text
[drag] enter
[drag] over
[drag] drop
[drag] chat drop target
[attachments] drop
[attachments] resolved paths
```

## 6. 附件限制与清理

- 单次最多保留 5 个待发送附件。
- 超过数量上限时，只接受剩余名额内的文件。
- 被忽略的多余附件会立即清理临时文件，并提示用户忽略数量。
- 单文件最大 20MB。
- 不支持的格式、文件过大、路径无法获取或复制失败时显示错误，不加入待发送列表。
- 用户手动移除待发送附件时，立即清理对应临时附件目录。

## 7. Windows 权限注意事项

Windows 文件拖放受 UIPI 权限隔离影响。开发时应使用普通权限 PowerShell 启动：

```powershell
npm run dev
```

如果 Electron 应用以管理员身份运行，而 Windows 文件资源管理器是普通权限，系统会直接禁止拖放，渲染进程不会收到任何 `dragenter`、`dragover` 或 `drop` 事件，也不会出现附件日志。

因此本应用不需要管理员权限运行。若必须使用管理员权限，拖放源进程也需要处于相同权限级别，但不建议将其作为默认使用方式。

## 8. 涉及模块

- `src/components/Message.tsx`：消息内附件展示、图片缩略图加载和文件类型图标。
- `src/components/Chat.tsx`：待发送附件、拖入文件路径获取、实际 drop 导入。
- `src/App.tsx`：主内容区原生拖放捕获、拖放状态和诊断日志。
- `src/index.css`：独立附件卡片、图片缩略图和拖放提示样式。
- `shared/attachments.ts`：附件预览引用字段。
- `electron/attachments.ts`：图片预览保存、读取和孤儿文件清理。
- `electron/main.ts`、`electron/preload.ts`、`src/types/electron.d.ts`：附件预览 IPC 接口。
