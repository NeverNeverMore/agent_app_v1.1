# 工具权限与用户确认 V2

> 版本：V2 ｜ 日期：2026-08-24 ｜ 状态：已完成开发，构建通过

## 一、功能范围

在 V1 只读工具调用基础上，增加 `file_write` 和用户确认闭环。`read` 工具继续自动执行；`write` 工具在主进程创建审批单并暂停 Agent 循环，用户批准或拒绝后恢复；`dangerous` 工具仍直接拒绝。本版本不包含删除、Shell、HTTP、数据库写入、多审批队列和审批日志页面。

## 二、审批模型

`shared/approvals.ts` 定义 `ApprovalRequest`，包含请求 ID、会话 ID、工具调用 ID、工具名、原始参数、参数 SHA-256 哈希、权限、状态、创建时间和过期时间。审批默认 5 分钟有效，状态包括 `pending`、`approved`、`rejected`、`expired`、`cancelled`。

审批记录仅保存在主进程内存中，消费后立即删除，因此审批 ID 不可复用。批准 IPC 必须同时提交参数哈希；主进程在批准和执行前均校验审批状态、有效期及哈希。

## 三、执行流程

1. 模型请求 `file_write`。
2. Agent 发出 `tool-event(start)`，主进程生成审批单并发出 `approval-event(request)`，循环等待决策。
3. 前端展示目标文件、创建/覆盖操作、内容字符数、内容摘要和批准/拒绝按钮。
4. 批准后主进程执行工具并恢复模型循环；拒绝、过期或取消则回填结构化错误，让模型自行说明结果。
5. `abort-message` 会取消请求下所有 pending 审批；前端同时将卡片持久化为已取消。

## 四、file_write 安全边界

- 仅允许写入会话关联的 `projectFolder`，拒绝绝对路径和 `..` 越界路径。
- 使用 UTF-8 写入，单次内容限制 200,000 字符。
- 自动创建目标文件的父目录，返回相对路径、UTF-8 字节数和 `created`（新建/覆盖）字段。
- 文件操作和权限判断全部在主进程完成，前端仅发起批准或拒绝请求。

## 七、会话权限模式

聊天输入区中“关联项目文件夹”右侧新增权限模式选择框，权限按会话保存，默认模式为“请求批准”。

### 请求批准

说明：`始终请求批准编辑外部文件和使用互联网`

- `read` 工具自动执行；
- `write` 工具必须显示确认卡片，用户批准后才执行；
- 拒绝、过期或停止会将结构化错误回填给模型；
- `file_write` 仍限制在关联项目文件夹内。

### 完全访问权限

说明：`不受限制地访问互联网和计算机上的任何文件`

- 当前项目没有互联网工具，该文案为后续联网能力预留；
- `read` 工具照常执行；
- `file_write` 跳过用户确认，可直接执行；
- 支持绝对路径和项目目录外路径；相对路径以关联项目目录为基准，没有关联目录时以应用当前工作目录为基准；
- `dangerous` 工具仍然拒绝执行，不会因为该模式自动开放。

完全访问模式会显著扩大文件写入范围，使用前应确认模型请求的目标路径和内容。权限模式只影响下一次发送的请求，生成过程中禁止切换，避免同一请求执行策略发生变化。

### 权限模式验收

1. 新建会话默认选择“请求批准”。
2. 切换到“完全访问权限”并刷新页面，当前会话仍保持该选择。
3. 请求批准模式下创建文件，批准前文件不存在，拒绝后不会写入。
4. 完全访问模式下创建或覆盖文件，不显示审批卡片并直接执行。
5. 完全访问模式下可使用绝对路径；请求批准模式下绝对路径和项目外路径被拒绝。
6. 两种模式下高危工具都不能执行。
## 八、权限选择器 UI

权限按钮位于聊天底部“关联项目文件夹”右侧。点击按钮后，向上弹出权限菜单，菜单中的每个选项均包含图标、中文标题、说明文字和当前选中状态。

- “请求批准”：始终请求批准编辑外部文件和使用互联网；
- “完全访问权限”：不受限制地访问互联网和计算机上的任何文件；
- 新建会话默认使用“请求批准”；
- 权限模式按当前会话保存；
- 生成过程中权限按钮禁用，避免同一请求执行策略发生变化；
- 选择完成后菜单自动关闭，点击外部区域或按 Escape 也会关闭菜单；
- 当前项目暂无互联网工具，互联网相关说明是后续能力预留。
