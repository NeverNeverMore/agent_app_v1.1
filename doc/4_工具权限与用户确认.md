# 工具权限与用户确认 V2

> 版本：V2 ｜ 日期：2026-08-24 ｜ 状态：已完成开发，构建通过

## 一、功能范围

在 V1 只读工具调用基础上，增加 `file_write` 和用户确认闭环。`read` 工具继续自动执行；`write` 工具在主进程创建审批单并暂停 Agent 循环，用户批准或拒绝后恢复；`dangerous` 工具仍直接拒绝。本版本不包含删除、Shell、HTTP、数据库写入、多审批队列和审批日志页面。

## 二、审批模型

`shared/approvals.ts` 定义 `ApprovalRequest`，包含请求 ID、会话 ID、工具调用 ID、工具名、原始参数、参数 SHA-256 哈希、权限、状态、创建时间和过期时间。审批默认 5 分钟有效，状态包括 `pending`、`approved`、`rejected`、`expired`、`cancelled`。

审批记录仅保存在主进程内存中，消费后立即删除，因此审批 ID 不可复用。批准 IPC 必须同时提交参数哈希；主进程在批准和执行前均校验审批状态、有效期及哈希。

## 三、执行流程

1. 模型请求 `file_write`。
2. Agent 发出 `tool-event(start)`，主进程生成审批单并发出 `approval-event(request)`，循环等待决策。
3. 前端展示目标文件、创建/覆盖操作、内容字符数、内容摘要和批准/拒绝按钮。
4. 批准后主进程执行工具并恢复模型循环；拒绝、过期或取消则回填结构化错误，让模型自行说明结果。
5. `abort-message` 会取消请求下所有 pending 审批；前端同时将卡片持久化为已取消。

## 四、file_write 安全边界

- 仅允许写入会话关联的 `projectFolder`，拒绝绝对路径和 `..` 越界路径。
- 使用 UTF-8 写入，单次内容限制 200,000 字符。
- 自动创建目标文件的父目录，返回相对路径、UTF-8 字节数和 `created`（新建/覆盖）字段。
- 文件操作和权限判断全部在主进程完成，前端仅发起批准或拒绝请求。
