# 内嵌个人知识库方案

## 1. 背景与目标

本项目是基于 Electron + React + TypeScript 的 Agent 桌面客户端。个人知识库的目标是让用户在当前客户端中保存、整理和检索长期可复用的资料，并让 Agent 在对话过程中按需使用这些资料。

知识库的设计目标如下：

- 面向个人使用，不引入多用户和复杂权限体系；
- 本地优先，数据默认保存在本机；
- 使用开源、轻量、可迁移的技术方案；
- 与现有 Agent 对话、项目和工具能力保持一致；
- 原始资料可直接备份、查看和迁移，不被专用数据库格式锁定；
- 先实现稳定的文本检索，再逐步增加语义检索能力。

## 2. 总体架构

推荐采用“文件为主、索引为辅”的架构：

```text
Electron / React 界面
        ↓
知识库服务层与 IPC API
        ↓
Markdown、TXT、原始附件
        ↓
SQLite 元数据与索引
        ├── SQLite FTS5：关键词搜索
        └── sqlite-vec：可选的语义搜索
```

### 3.1 原始数据

Markdown 是主要的可编辑内容格式。笔记正文直接保存为普通 `.md` 文件，用户可以用外部编辑器查看、备份和迁移。

TXT、JSON、CSV、HTML 等文本文件可以直接读取并导入。PDF、DOCX、XLSX、PPTX 等复杂格式保留原文件，同时提取文本用于搜索和 Agent 检索。

### 3.2 索引数据

SQLite 用于保存笔记元数据、文件路径、标签、更新时间、导入状态和搜索索引。SQLite FTS5 负责第一阶段的关键词搜索。`sqlite-vec` 作为可选组件，在后续阶段保存文本片段的 embedding 并提供语义相似度搜索。

索引是可重建数据，不应成为用户唯一的数据来源。即使索引损坏，也应支持从笔记和原始文件重新建立索引。

### 3.3 推荐目录

```text
knowledge-base/
├── notes/          # 可编辑的 Markdown 笔记
├── originals/      # 导入的 PDF、DOCX、XLSX、PPTX 等原始文件
├── assets/         # 图片及其他附件
└── index.sqlite    # 元数据、全文索引和可选向量索引
```

知识库根目录建议由用户选择或在 Electron 的用户数据目录下创建。文件路径必须经过现有路径安全校验逻辑，避免越权读写任意位置。

## 3. 界面设计

### 4.1 全局左侧菜单

在当前应用的左侧功能菜单中新增一个一级入口“知识库”，与“新对话、工具、Skills、MCP、会话归档”等功能同级：

```text
新对话
工具
Skills
MCP
知识库
会话归档
```

点击“知识库”后，右侧主界面切换为知识库页面。知识库不需要在全局左侧菜单中展开每一篇笔记。

### 4.2 知识库主界面

知识库主界面内部可以采用三栏工作台：

```text
知识库主界面
├── 顶部工具栏：搜索、导入文件、新建笔记
├── 局部导航：全部笔记、最近编辑、收藏、文件夹、标签
├── 笔记列表：标题、更新时间、文件类型、来源
└── 编辑区：Markdown 编辑器或预览
```

“全部笔记、文件夹、收藏、标签”等属于知识库页面内部的局部导航，不属于应用全局菜单。

第一版可以简化为顶部工具栏加笔记列表，暂不实现复杂的二级路由。随着笔记数量增加，再在主界面内部增加文件夹树、标签栏和关联内容区域。

### 4.3 与现有界面的一致性

知识库应遵循当前客户端的交互模式：点击左侧一级菜单，右侧主区域展示对应功能。知识库内部的新增、编辑、导入和搜索都在右侧主区域完成，不改变现有全局导航结构。

## 4. 文件导入与内容管理

### 5.1 文本文件

以下格式可以作为可编辑内容或直接建立全文索引：

- Markdown：`.md`、`.markdown`
- 纯文本：`.txt`
- 结构化文本：`.json`、`.csv`
- 网页文本：`.html`

导入后可以复制到知识库的 `notes/` 目录，也可以保留原路径并记录引用关系。第一版建议复制到知识库目录，降低外部文件被移动后失效的风险。

### 5.2 复杂文档

以下格式需要解析器提取文本：

- PDF：保留原始 PDF，提取正文和页码信息；
- DOCX：提取段落和表格文本；
- XLSX：提取工作表名称和单元格内容；
- PPTX：提取幻灯片标题和正文。

导入复杂文件时应同时保存原文件和提取结果。提取结果用于搜索和 Agent 问答，原文件用于用户查看和追溯来源。不要直接用提取文本覆盖原始 PDF 或 DOCX。

### 5.3 导入交互

知识库应支持：

- 文件选择器导入；
- 拖拽文件导入；
- 批量导入多个文件；
- 导入进度和失败提示；
- 重复文件检测；
- 手动重建单个文件或整个知识库的索引。

## 5. Agent 集成

知识库需要向 Agent 暴露稳定、最小化的工具接口：

### `search_knowledge`

根据关键词或自然语言查询知识库，返回相关笔记、文件、片段、路径和来源信息。第一版使用 FTS5，接入向量检索后可以支持混合搜索。

### `read_note`

读取指定笔记或导入文件的内容，支持按文档 ID、相对路径或搜索结果引用读取。返回内容时应保留来源和文件名。

### `create_note`

创建新的 Markdown 笔记，支持标题、正文、文件夹、标签和来源信息。默认写入 `notes/` 目录。

### `update_note`

更新已有 Markdown 笔记，修改后同步刷新全文索引和向量索引。

### 对话内操作

知识库应支持以下对话场景：

- 用户要求 Agent 搜索个人资料；
- Agent 读取相关笔记后回答问题；
- 用户将当前回答保存为新笔记；
- 用户要求 Agent 整理多个文件并生成摘要笔记；
- 用户要求更新已有知识条目。

所有写入操作应遵循当前 Agent 的工具审批和错误恢复机制。

## 6. 检索方案

### 第一阶段：关键词检索

使用 SQLite FTS5 对标题、正文、标签和提取文本建立全文索引。该方案不需要额外服务，适合第一版桌面应用。

### 第二阶段：语义检索

在文本按段落切分后生成 embedding，使用 `sqlite-vec` 保存和查询向量。向量索引应与原始文档 ID、段落序号和来源路径关联。

### 推荐的混合检索流程

```text
用户问题
   ├── FTS5 关键词检索
   └── sqlite-vec 语义检索
          ↓
合并、去重、排序
          ↓
返回相关文档片段给 Agent
```

语义检索不应替代关键词检索。文件名、专有名词、错误码和精确标识符通常更适合关键词搜索。

## 7. 实施阶段

### 第一阶段：可用的本地知识库

- 在左侧全局菜单增加“知识库”；
- 增加知识库主界面；
- 支持 Markdown 和 TXT 的新建、读取、编辑、删除；
- 支持文件夹和基础搜索；
- 支持文本文件导入；
- 建立基础 SQLite 元数据和 FTS5 索引；
- 增加拖拽导入和导入失败提示。

### 第二阶段：文档导入和 Agent 工具

- 支持 PDF 文本提取；
- 逐步支持 DOCX、XLSX、PPTX；
- 保留原始附件并记录提取状态；
- 增加 `search_knowledge`、`read_note`、`create_note`、`update_note`；
- 支持从对话中保存和整理知识。

### 第三阶段：语义检索

- 接入 embedding 生成流程；
- 引入 `sqlite-vec`；
- 实现文本切分、向量写入和增量更新；
- 支持关键词和语义混合检索；
- 支持批量重建向量索引。

### 后续阶段：增强管理能力

- 标签和收藏；
- 最近编辑和关联笔记；
- 引用来源和文档片段定位；
- 索引状态查看和批量重建；
- 知识库导出和备份；
- 根据实际使用情况评估同步和加密能力。

## 8. 实现边界

### 第一版明确不做的能力

- 多用户和复杂权限；
- 云同步和团队协作；
- 完整知识图谱；
- 复杂富文本编辑器；
- 多服务编排；
- 自动覆盖或修改用户原始文件。

## 9. 验收标准

第一阶段完成后应满足：

- 用户可以从左侧菜单进入知识库；
- 用户可以新建、编辑、删除 Markdown 笔记；
- 用户可以导入 Markdown 和 TXT 文件；
- 用户可以按标题、正文和文件名搜索；
- 知识库数据可以在本地目录中直接查看和备份；
- 导入或编辑失败时不会破坏原始笔记；
- 索引删除后可以从文件重新建立；
- 知识库界面不会改变现有对话、工具和会话归档的使用方式。
