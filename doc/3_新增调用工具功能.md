# 新增调用工具功能（V1）

> 版本：V1 ｜ 日期：2026-08-21 ｜ 状态：已完成开发，构建通过

## 一、功能概述

在原有“对话 + 流式输出 + 停止 + 历史记录”的基础上，新增**统一工具调用框架**，使应用从纯聊天界面升级为具备基础 Agent 能力的形态：

```text
用户消息
  ↓
模型判断是否需要工具
  ↓
后端统一校验并执行工具（只读、低风险）
  ↓
工具结果回填上下文
  ↓
模型基于结果生成最终回答
  ↓
前端展示工具执行卡片 + 流式回答
```

V1 只开放**只读、无副作用**的工具；写入/高危工具的权限字段与审批错误码已预留，确认流程在 V2 实现。

## 二、整体架构

```text
渲染进程（React）                        主进程（Electron）
─────────────────                      ─────────────────
useChat.sendMessage ──send-message──▶  main.ts
   │                                      └─ agentLoop.runAgentLoop（最多 8 步循环）
   │                                         ├─ 请求模型（携带 tools schema）
   │                                         ├─ 流式解析 content + tool_calls
   │                                         ├─ executor.executeToolCall
   │                                         │    ├─ JSON 参数解析
   │                                         │    ├─ schema 参数校验
   │                                         │    ├─ 权限检查（仅 read 自动执行）
   │                                         │    ├─ 30s 超时 / AbortSignal 取消
   │                                         │    └─ 结果截断（20K 字符）
   │                                         └─ 工具结果回填 messages，继续循环
   ◀── stream-chunk / tool-event ────────────┘
        stream-done / stream-error
Message.tsx 渲染工具卡片（执行中/成功/失败 + 耗时，可展开参数与结果）
```

## 五、内置工具（V1，均为 read 权限）

| 工具 | 说明 | 安全边界 |
|---|---|---|
| `time_current` | 获取当前日期时间（ISO / 本地 / 时区 / 时间戳） | 无副作用 |
| `calculator_calculate` | 计算数学表达式（+ - * / %、括号、负数） | 手写递归下降解析器，不使用 eval/Function |
| `file_list` | 列出项目文件夹内目录内容（相对路径，最多 200 条） | 路径必须解析在项目文件夹内 |
| `file_read` | 读取项目文件夹内文本文件（超 100K 字符截断） | 路径必须解析在项目文件夹内，拒绝 `..` 越界 |

文件工具依赖会话关联的项目文件夹（`Conversation.projectFolder`），未关联时返回明确错误提示。当关联了项目文件夹时，agentLoop 会自动注入一条 system 消息，告知模型项目目录与路径约束。

## 六、统一工具接口

```ts
interface ToolDefinition {
  name: string                                  // 如 file_read
  description: string                           // 告知模型何时使用
  inputSchema: ToolInputSchema                  // JSON Schema 子集
  permission: 'read' | 'write' | 'dangerous'    // 权限等级
  execute(args, context): Promise<ToolResult>   // 真正执行
}

interface ToolContext {
  projectFolder: string
  signal: AbortSignal                           // 支持用户停止
}

interface ToolResult {
  success: boolean
  output?: unknown
  error?: { code: string; message: string; retryable: boolean }
}
```

新增工具只需实现该接口并 `registry.register()`，无需改动核心对话循环。

## 七、权限与安全边界（V1）

- **权限分级**：每个工具声明 `permission`，V1 仅 read 工具暴露给模型并自动执行。
- **预留审批**：write / dangerous 工具即使被模型请求，执行器也返回 `APPROVAL_REQUIRED` 结构化错误，V2 接入用户确认流程（审批 ID、确认卡片、批准/拒绝、审计）。
- **路径约束**：文件工具统一经 `resolveWithinRoot` 解析，拒绝项目文件夹之外的路径。
- **资源限制**：工具执行 30s 超时；结果回传模型前截断至 20K 字符；目录列表最多 200 条；文件读取最多 100K 字符。
- **循环上限**：工具调用循环最多 8 步，最后一步不再携带 tools，强制模型基于已有结果输出最终回答，防止无限调用。
- **停止联动**：复用现有停止机制，`AbortSignal` 贯穿模型流与工具执行，停止后已生成内容保留。

## 八、工具错误码

| 错误码 | 含义 |
|---|---|
| `TOOL_NOT_FOUND` | 模型请求了未注册的工具 |
| `INVALID_ARGUMENTS` | 参数不是合法 JSON 对象 / schema 校验失败 |
| `APPROVAL_REQUIRED` | 非 read 工具，需用户确认（V2 开放） |
| `TOOL_TIMEOUT` | 执行超过 30 秒 |
| `TOOL_ABORTED` | 用户停止 |
| `TOOL_EXECUTION_ERROR` | 工具内部未捕获异常 |
| `FILE_ACCESS_ERROR` | 文件工具路径越界 / 读取失败 |
| `INVALID_EXPRESSION` | 计算器表达式非法 |

所有错误以结构化 JSON 回传模型（`{"error":{code,message}}`），模型可自行恢复并向用户解释，不会导致整个请求崩溃。

## 九、前端展示

- 工具调用以卡片形式展示在 assistant 消息上方：工具名 + 状态（执行中 / 成功·耗时 / 失败）。
- 卡片可展开查看参数与结果摘要（400 字符截断）。
- 工具调用记录随消息持久化（`Message.toolCalls`），刷新后仍可回看执行过程。

## 十、验证情况

- `npm run build`（tsc + vite 三端打包）通过，`tsc --noEmit` 零错误。
- 待人工联调用例：
  1. 普通问答回归（不触发工具，行为与之前一致）
  2. “现在几点了” → `time_current` 卡片
  3. “算一下 (123+456)*7” → `calculator_calculate`，结果 4053
  4. 关联项目文件夹后“这个项目有哪些文件” → `file_list` / `file_read` 多轮调用
  5. 生成中点停止 → 工具执行被取消，已生成内容保留
  6. 诱导读取 `../外部路径` → `FILE_ACCESS_ERROR: 路径越界`

## 十一、已知限制与后续计划

- 依赖模型供应商支持 OpenAI 风格 `tools` / `tool_calls`（kimi-k2 系列支持）；若模型不返回工具调用，需先确认模型能力。
- V2 计划：用户确认流程（write/dangerous 工具、审批 ID、确认卡片、批准/拒绝、待审批任务持久化与恢复、审计日志）、工具失败重试、文件上传与分析、更多工具（搜索、HTTP、代码执行沙箱）。
