## 一、项目概述

- **项目名称**：`sifang-chat-client`（原 kimi-chat-client）
- **类型**：Electron + React + TypeScript 桌面聊天客户端
- **目标**：从纯大模型对话应用逐步升级为具备工具调用、文件分析和审批确认的本地 Agent
- **运行平台**：Windows（当前主要目标），Electron 跨平台可扩展
- **技术栈**：
  - 前端：React 18 + Vite 5
  - 后端/主进程：Electron 32 + Node.js 原生模块
  - 协议：OpenAI 兼容接口 / Anthropic 接口
  - 本地解析：mammoth（DOCX）、xlsx（Excel）、pdf-parse（PDF）、jszip（Office/PPTX）
- **打包命令**：`npm run dist:win`
- **开发命令**：`npm run dev`
- **构建命令**：`npm run build`
- **测试命令**：`npm test`

## 四、核心架构

### 1. 请求链路

```text
用户输入/附件
  → Chat.tsx
  → useChat.sendMessage(content, attachments)
  → electronAPI.sendMessage(payload)
  → electron/main.ts send-message handler
  → prepareAttachments
  → runAgentLoop
  → protocol.requestModel
  → 流式返回 / 工具调用
```

### 2. 工具调用循环

`electron/agentLoop.ts` 中的 `runAgentLoop`：

- 每次请求最多 8 步工具调用循环；
- 最后一步不再携带 tools，强制模型输出最终回答；
- 工具执行前进行 schema 校验；
- `read` 工具自动执行；
- `write` 工具在 `ask` 模式下生成审批并暂停循环；
- `dangerous` 工具始终拒绝；
- `full` 模式下 `file_write` 跳过审批，允许绝对路径和项目目录外路径。

### 3. IPC 事件

| 事件 | 方向 | 说明 |
|---|---|---|
| `send-message` | 渲染 → 主进程 | 发送聊天请求 |
| `abort-message` | 渲染 → 主进程 | 停止当前请求 |
| `stream-chunk` | 主进程 → 渲染 | 流式文本片段 |
| `stream-done` | 主进程 → 渲染 | 请求完成 |
| `stream-error` | 主进程 → 渲染 | 请求失败 |
| `tool-event` | 主进程 → 渲染 | 工具开始/结果事件 |
| `approval-event` | 主进程 → 渲染 | 审批请求/状态更新 |
| `task-status` | 主进程 → 渲染 | 任务状态变更 |
| `select-folder` | 渲染 → 主进程 | 选择项目文件夹 |
| `select-attachments` / `import-attachments` / `cleanup-attachments` | 双向 | 附件处理 |
| `approve-tool` / `reject-tool` | 渲染 → 主进程 | 审批操作 |
| `list-pending-approvals` | 渲染 → 主进程 | 页面刷新恢复待审批 |

## 五、工具系统

### 1. 内置工具

| 工具名 | 权限 | 说明 | 安全边界 |
|---|---|---|---|
| `time_current` | read | 获取当前时间 | 无副作用 |
| `calculator_calculate` | read | 计算数学表达式 | 手写解析器，无 eval |
| `file_list` | read | 列出项目目录内容 | 限制在项目目录内 |
| `file_read` | read | 读取项目目录内文本文件 | 限制 100K 字符 |
| `file_write` | write | 写入文件 | ask 模式需审批；full 模式允许项目外路径 |

### 2. 新增工具方式

实现 `electron/tools/types.ts` 中的 `ToolDefinition` 接口，然后在 `electron/tools/index.ts` 的 `createRegistry()` 中注册：

```ts
import { registerMyTool } from './builtins'
const registry = new ToolRegistry()
registry.register(myTool)
return registry
```

工具名必须满足正则 `/^[a-zA-Z][a-zA-Z0-9_-]*$/`。

### 3. 权限分级

- `read`：只读，自动执行；
- `write`：写入/修改，ask 模式需用户确认；
- `dangerous`：高危（Shell、HTTP、删除等），当前版本不暴露给模型。

## 六、权限模式

### ask（请求批准，默认）

- `read` 工具自动执行；
- `file_write` 显示审批卡片，用户批准后才执行；
- `file_write` 限制在关联项目目录内；
- 未关联项目目录时文件工具报错。

### full（完全访问权限）

- `read` 工具自动执行；
- `file_write` 跳过审批，直接执行；
- 允许绝对路径和项目目录外路径；
- 相对路径以项目目录为基准，未关联时以应用当前工作目录为基准；
- `dangerous` 工具仍然被拒绝。

### UI 位置

聊天底部“关联项目文件夹”按钮右侧，点击后弹出权限菜单。

## 七、文件上传与附件分析

### 支持的文件类型

- 文本：`.txt`、`.md`、`.json`、`.csv`、代码文件等；
- 图片：`.png`、`.jpg`、`.jpeg`、`.webp`；
- PDF：`.pdf`；
- Office：`.docx`、`.xlsx`、`.xls`、`.pptx`。

### 流程

```text
选择文件/拖拽文件
  → 校验扩展名、文件头、大小（单文件 ≤20MB，单次 ≤5 个）
  → 复制到 Electron 临时目录
  → 本地解析为文本/图片 data URL
  → 注入模型上下文
  → 任务完成后 10 分钟清理临时文件
```

### 限制

- 单文件最大 20MB；
- 单次最多 5 个附件；
- 文本提取单文件最多 100,000 字符；
- 所有附件合计最多 180,000 字符；
- 页面刷新后临时附件不恢复；
- 附件只读，不影响 `file_write` 权限边界。

## 八、任务状态与错误恢复

任务状态（`shared/task.ts`）：

```ts
type TaskStatus = 'queued' | 'preparing_attachments' | 'parsing_attachments' | 'generating' | 'waiting_approval' | 'running_tool' | 'completed' | 'failed' | 'cancelled'
```

- 失败时前端显示“任务执行失败，可以重试”；
- 重试会移除末尾失败占位消息，复用最近的用户消息；
- 用户停止后 `AbortSignal` 贯穿模型流和工具执行；
- 页面刷新后可通过 `list-pending-approvals` 恢复未决审批。

## 九、持久化机制

### 前端 localStorage

- 会话历史：`chat-conversations-state`
- API 配置：`api-config`

### 主进程用户数据目录

- 审批记录：`<userData>/pending-approvals.json`
- 临时附件：`<temp>/attachments/<随机目录>/`

应用启动时清理超过 1 小时的孤立附件目录；应用重启后遗留审批会被清理，不会误执行。

## 十一、开发注意事项

1. **编码问题**：部分文件内容可能因 Windows/PowerShell 出现中文乱码（显示为 `锟` 系列字符），实际运行时 Electron 内置 Chromium 通常能正常显示；若文档出现乱码，优先用 UTF-8 编码保存。
2. **路径安全**：所有文件工具路径必须通过 `electron/tools/pathSecurity.ts` 校验；新增文件工具时务必复用现有安全函数。
3. **IPC 类型**：修改主进程 preload 暴露的 API 后，必须同步更新 `src/types/electron.d.ts`。
4. **工具命名**：工具名必须满足 `/^[a-zA-Z][a-zA-Z0-9_-]*$/`，否则会报错。
5. **模型兼容**：当前协议适配 OpenAI 风格（`tools`/`tool_calls`）和 Anthropic；若模型不返回工具调用，检查模型能力。
6. **Electron 拖拽**：文件拖拽依赖 `webUtils.getPathForFile`，已在 `Chat.tsx` 中做窗口级事件捕获。
7. **完全访问模式风险**：`full` 模式下 `file_write` 可写任意本地路径，属于高风险能力，UI 已有明确中文说明。
8. **停止行为**：停止请求会取消 pending 审批、停止模型流和工具执行；已生成内容保留。
9. **权限模式作用域**：按会话保存，只影响下一次发送的请求，不影响正在执行的请求。

## 十二、后续可继续做的方向

1. **长上下文压缩**：对话历史超过模型上下文窗口时自动摘要、截断或保留关键消息。
2. **更多工具**：Shell 执行沙箱、Web 搜索、数据库查询、代码解释器等。
3. **审批历史与审计日志**：记录已批准/拒绝的操作，支持查看历史。
4. **全局/项目级记忆**：跨会话共享项目知识，自动注入系统提示。
5. **网络重试与指数退避**：模型请求失败后的自动重试策略。
6. **多模态增强**：图片 OCR、视频/音频文件支持。
7. **跨窗口同步**：多个 Electron 窗口间同步会话和审批状态。
8. **设置项持久化改进**：把部分配置迁移到主进程 `userData`。
