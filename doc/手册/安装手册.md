# LINGQI(令旗)桌面客户端 Agent 安装手册

## 1. 安装方式选择

项目支持两种使用方式：

1. 开发环境运行：适合开发、调试和功能验证；
2. Windows 安装包或免安装版本：适合测试和交付使用。

安装包由 `electron-builder` 生成，输出目录为项目根目录下的 `release/`。

## 2. 开发环境安装

### 2.1 环境要求

- Windows 10/11；
- Node.js 18 或更高版本；
- npm；
- 能访问 npm registry 和目标模型 API；
- 如果使用 MCP，需要额外安装对应 MCP Server 的运行环境，例如 Node.js 或 Python。

检查环境：

```powershell
node -v
npm -v
```

### 2.2 获取项目并安装依赖

进入项目目录：

```powershell
cd ~\agent_app_v1.1
```

首次安装推荐：

```powershell
npm ci
```

如果没有锁定文件或需要更新依赖，可使用：

```powershell
npm install
```

安装 Electron 二进制时若出现证书错误，可在当前 PowerShell 窗口临时设置：

```powershell
$env:NODE_OPTIONS='--use-system-ca'
npm ci
```

该环境变量只影响当前窗口，不需要永久写入系统环境变量。

### 2.3 启动开发环境

```powershell
npm run dev
```

Vite 会启动开发服务器，Electron 会自动打开客户端窗口。修改 `src/`、`electron/` 或 `shared/` 后，开发环境会按配置重新加载。

## 3. 生产构建和打包

### 3.1 构建检查

```powershell
npm run build
```

该命令包括：

1. TypeScript 类型检查；
2. 构建 React 前端到 `dist/`；
3. 构建 Electron 主进程和 preload 到 `dist-electron/`。

### 3.2 运行测试

```powershell
npm test
```

测试覆盖附件限制和解析、审批流程、路径安全、Skill 解析及 UTF-8 编码检查。

### 3.3 生成 Windows 安装包

```powershell
npm run dist:win
```

也可以使用：

```powershell
npm run dist
```

打包产物：

```text
release/
├─ win-unpacked/                         免安装版本
└─ 四方上行 Chat Client Setup 0.1.0.exe   Windows 安装程序
```

实际文件名以 `electron-builder.yml` 和当前版本配置为准。安装程序支持自定义安装目录，并默认创建桌面快捷方式和开始菜单快捷方式。

## 4. 安装和启动客户端

### 4.1 使用安装程序

双击 `release` 目录下的 Setup `.exe`，按向导选择安装目录。安装完成后，从桌面快捷方式或开始菜单启动。

### 4.2 使用免安装版本

直接运行：

```text
release\win-unpacked\四方上行 Chat Client.exe
```

免安装版本适合临时测试，不会替代旧版本安装，也不会自动更新。

## 5. 首次配置

客户端首次启动后：

1. 打开“设置”；
2. 填写 API 密钥、协议、API 地址和模型；
3. 点击“检测连通”；
4. 点击“保存”；
5. 在聊天页面关联需要操作的项目目录。

API 密钥会保存在当前应用的 `localStorage` 中。请勿在共享 Windows 账户或不受控电脑上保存生产密钥。

## 6. MCP 安装配置

MCP Server 不会自动随客户端安装包提供。需要先单独安装对应 Server，再在客户端 MCP 页面配置启动命令。

配置字段：

```json
[
  {
    "name": "filesystem",
    "command": "npx",
    "args": [
      "-y",
      "@modelcontextprotocol/server-filesystem",
      "D:\\Workspaces\\demo"
    ],
    "env": {},
    "enabled": true
  }
]
```

注意事项：

- 当前版本只支持本地 `stdio` MCP Server；
- `command` 必须能在客户端启动环境中执行；
- `args` 中的路径必须真实存在且权限足够；
- 环境变量中的密钥会传给 MCP 子进程；
- MCP 配置保存在 Electron `userData/mcp-servers.json`；
- 未标注为只读的 MCP 工具会按写入操作处理并触发审批；
- 标记为危险的 MCP 工具在当前版本会被拒绝执行。

## 7. Skill 安装配置

### 全局 Skill

将目录放到 Electron 用户数据目录下：

```text
<userData>\skills\<skill-name>\SKILL.md
```

### 项目 Skill

将目录放到关联项目目录下：

```text
<项目目录>\.agent\skills\<skill-name>\SKILL.md
```

`SKILL.md` 至少应包含：

```markdown
---
name: code-review
description: 代码审查规范
version: 1.0.0
tags: [code, review]
---

执行代码审查时优先检查正确性、安全边界和测试覆盖。
```

单个 `SKILL.md` 最大 64 KB。安装后在客户端 Skills 页面点击刷新，确认 Skill 显示正常，再为当前会话勾选启用。

## 8. 数据备份和迁移

需要迁移本地配置时，可备份以下内容：

- `localStorage` 中的 `api-config` 和 `chat-conversations-state`；
- Electron `userData/pending-approvals.json`；
- Electron `userData/mcp-servers.json`；
- Electron `userData/skills/`；
- 项目目录下的 `.agent/skills/`。

会话和 API 配置不由项目目录保存，也不会随着项目文件自动迁移。生产环境迁移前请先退出客户端，并妥善保护 API 密钥。

## 9. 升级和重新打包

升级源码后建议执行：

```powershell
cd ~\agent_app_v1.1
git status
npm ci
npm test
npm run dist:win
```

如果客户端仍显示旧功能，通常是启动了旧目录中的 `.exe`，或代码更新后没有重新打包。请确认执行文件来自本次构建生成的 `release/win-unpacked/`。

## 10. 常见安装问题

### Electron 依赖安装失败

先尝试：

```powershell
$env:NODE_OPTIONS='--use-system-ca'
npm ci
```

同时确认代理、证书和网络访问权限。

### 打包时报符号链接权限错误

使用管理员身份打开 PowerShell 后重试：

```powershell
npm run dist:win
```

也可以开启 Windows 开发者模式后重新打包。即使安装程序生成失败，`release/win-unpacked/` 有时仍可用于测试。

### 启动后无法调用模型

检查 API 地址是否包含正确的基础路径、协议是否匹配、API 密钥是否有效、模型 ID 是否存在，以及当前网络是否能访问模型服务。

### MCP 显示连接失败

先在 PowerShell 中单独执行 MCP 的 `command` 和 `args`，确认运行环境、路径和环境变量正确，再回到客户端点击重连。

## 11. 卸载

通过 Windows“应用和功能”卸载安装版客户端。卸载程序和应用数据是否一并删除取决于 Windows 和 Electron 的数据目录处理方式；如需彻底清理，请在确认不再需要后手动备份并删除对应 `userData` 目录。
