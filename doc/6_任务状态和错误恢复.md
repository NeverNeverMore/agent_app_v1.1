# 6_任务状态和错误恢复

## 一、功能概述

本次为 Agent 请求增加统一任务状态链路，覆盖模型生成、审批等待、工具执行、完成、失败和取消等阶段。状态由主进程产生，通过 IPC 推送到渲染进程，前端据此显示当前进度并提供失败重试入口。

## 二、任务状态

共享类型位于 `shared/task.ts`，当前状态包括：

- `queued`：请求已创建，等待 Agent 循环启动；
- `generating`：正在请求模型或处理工具结果；
- `waiting_approval`：等待用户批准写入工具；
- `running_tool`：正在执行工具；
- `completed`：任务正常完成；
- `failed`：模型请求或 Agent 流程发生错误；
- `cancelled`：用户停止任务或请求被取消。

主进程新增 `task-status` 事件，携带请求 ID 和状态。渲染进程只接收当前请求的事件，避免旧请求的状态污染新请求。

## 三、错误恢复

当任务失败时：

1. 主进程发送 `failed` 状态和错误信息；
2. 前端结束加载状态，并保留错误消息；
3. 输入框上方显示“任务执行失败，可以重试”；
4. 用户点击“重试”后，使用最近一次用户消息重新发起任务；
5. 重试会移除末尾失败占位消息，避免重复保留错误回复。

工具自身返回的业务失败仍会作为工具结果交给模型，Agent 可以根据错误继续处理；只有未捕获的模型/流程异常才会把整个任务标记为 `failed`。

## 四、停止与审批一致性

- 用户点击停止后，AbortSignal 取消模型请求和正在执行的工具；
- 待审批请求继续通过现有审批管理器标记为 `cancelled`；
- 主进程最终发送 `cancelled` 状态，不再显示任务执行中；
- 页面刷新恢复待审批请求时，前端将任务状态恢复为 `waiting_approval`。
