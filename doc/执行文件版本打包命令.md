# 执行文件版本打包命令

本文说明如何将当前 Git 分支中的最新代码打包为 Windows Electron 可执行版本。

## 一、确认打包目录和分支

打包前先进入需要发布的工作目录，并确认当前分支。例如，打包合并后的 `master` 版本：

```powershell
cd D:\root\codex\workspace\agent_app_v1.1
git branch --show-current
git status
```

如果要打包开发分支，应进入对应的 worktree：

```powershell
cd D:\root\codex\workspace\agent_app_v1.2
git branch --show-current
```

只有确认代码已经合并到目标分支后，才能得到对应版本的执行文件。

## 二、安装依赖

新 worktree 或首次打包时，先安装依赖：

```powershell
npm ci
```

如果项目没有 `package-lock.json`，可以使用：

```powershell
npm install
```

如果依赖安装遇到证书问题，可在当前 PowerShell 窗口临时执行：

```powershell
$env:NODE_OPTIONS='--use-system-ca'
npm ci
```

## 三、打包 Windows 版本

推荐直接执行：

```powershell
npm run dist:win
```

该命令会依次完成：

1. 执行 TypeScript 类型检查。
2. 构建前端文件到 `dist/`。
3. 构建 Electron 主进程和 preload 到 `dist-electron/`。
4. 使用 `electron-builder` 生成 Windows 版本到 `release/`。

也可以拆开执行，便于定位问题：

```powershell
npm run build
npx electron-builder --win
```

## 四、运行打包后的客户端

免安装版本位于：

```text
D:\root\codex\workspace\agent_app_v1.1\release\win-unpacked\四方上行 Chat Client.exe
```

如果是在 `agent_app_v1.2` 中打包，执行文件位于：

```text
D:\root\codex\workspace\agent_app_v1.2\release\win-unpacked\四方上行 Chat Client.exe
```

请运行与当前打包目录对应的执行文件，不要继续打开旧目录下的 `.exe`。

## 五、版本不一致时的处理

`npm run dev` 使用当前源码，而 `.exe` 使用上一次打包生成的文件。合并分支后，旧的 `release/` 不会自动更新，因为它是 Git 忽略的构建产物。

遇到执行文件版本不对时，按以下步骤重新打包：

```powershell
cd D:\root\codex\workspace\agent_app_v1.1
git pull
npm run dist:win
```

如果旧客户端仍在运行，请先完全退出，再执行打包命令。必要时可删除旧的 `release/` 后重新打包，但删除前请确认目录中没有需要保留的发布文件。

## 六、常用命令

```powershell
# 启动开发环境
npm run dev

# 仅检查并构建项目
npm run build

# 打包当前平台版本
npm run dist

# 仅打包 Windows 版本
npm run dist:win
```

## 七、打包结果是否进入 Git

以下目录属于自动生成的构建产物，默认被 `.gitignore` 忽略，不会随分支提交：

- `node_modules/`
- `dist/`
- `dist-electron/`
- `release/`
- `*.log`

因此，换到另一个 worktree 后需要重新执行 `npm ci` 和 `npm run dist:win`。

## 八、常见问题

### 1. `release/` 中的执行文件还是旧版本

通常是因为运行了旧目录中的 `.exe`，或者合并代码后没有重新执行 `npm run dist:win`。请确认当前目录、当前分支和执行文件路径一致。

### 2. 打包时出现 `winCodeSign` 或符号链接权限错误

可以用管理员身份打开 PowerShell 后重新执行：

```powershell
npm run dist:win
```

也可以开启 Windows 开发者模式后再打包。即使安装程序生成失败，`release/win-unpacked/` 中的免安装版本有时仍然可以用于测试。

### 3. 如何确认执行文件来自哪个提交

打包前记录当前提交：

```powershell
git log -1 --oneline
```

然后重新执行 `npm run dist:win`，并运行本次打包生成的 `release/win-unpacked/四方上行 Chat Client.exe`。
