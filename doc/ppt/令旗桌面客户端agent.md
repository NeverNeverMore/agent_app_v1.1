## 三、产品背景与定位

### 3.1 为什么需要桌面 Agent

企业真实工作并不只发生在网页对话框中。业务资料、项目代码、历史技术资产、制度文件、表格和演示文档往往保存在本机或受控目录内。纯网页对话工具无法安全地访问这些上下文，也无法把文件、工具执行、人工确认和任务状态串成完整流程。

实际使用中通常存在四类问题：

1. **工作上下文分散**：模型、文件、检索、工具和业务系统之间需要人工来回切换。
2. **本地文件使用门槛高**：用户需要先整理、上传、转换文件，再向模型描述任务。
3. **敏感数据安全压力大**：API Key、内部文档和任务过程不适合无边界地交给外部平台。
4. **长任务缺乏可恢复性**：网络波动、工具失败或用户停止后，任务容易从头开始。

### 3.2 产品定位

令旗是一个本地优先的桌面 Agent 工作台。它以 Electron 桌面客户端为载体，将大模型、会话、项目目录、文件附件、工具、MCP 服务、Skill 和权限审批统一到一个可追踪的工作空间中。

令旗不是为了替代企业现有业务系统，而是作为连接本地文件、企业知识和受控工具的通用 Agent 入口，补足临时性、非固定性和跨文件的工作需求。

### 3.3 产品价值

| 价值    | 说明                                       |
| ----- | ---------------------------------------- |
| 本地优先  | 文件处理和工具执行在本机完成，适合对数据边界有要求的场景。            |
| 使用简单  | 用户以自然语言描述任务，无需先掌握复杂工具命令。                 |
| 能力可扩展 | 内置工具、MCP 服务和 Markdown Skill 可以持续增加专业能力。  |
| 过程可控  | 工具按 read、write、dangerous 分级，写入操作可要求用户审批。 |
| 任务可追踪 | 会话、工具调用、任务状态、审批状态和错误信息在界面中可见。            |

## 四、客户端功能全景

### 4.1 模型与对话

- 支持 OpenAI 兼容协议和 Anthropic 协议。
- 支持 Base URL、API Key、模型 ID 和协议独立配置。
- 支持 SSE 流式输出，实时显示模型生成内容。
- 支持停止生成、失败重试和联通性检测。
- 对话通过 Electron 主进程发起，避免渲染进程直接处理密钥请求。

### 4.2 会话工作台

- 支持新建、切换、重命名和删除会话。
- 会话保存消息上下文、项目目录、权限模式和当前启用的 Skill。
- 支持将会话关联到一个本地项目文件夹。
- 会话状态通过 `localStorage` 持久化，应用重启后可以恢复历史会话。
- 左侧边栏统一提供 Chat、Tools、Skills 和 MCP 入口。

### 4.3 文件上传与分析

支持的主要文件类型包括：

- 文本和代码：`.txt`、`.md`、`.json`、`.csv` 及常见代码文件；
- 图片：`.png`、`.jpg`、`.jpeg`、`.webp`；
- 文档：`.pdf`、`.docx`；
- 表格：`.xlsx`、`.xls`；
- 演示文档：`.pptx`。

附件处理流程为：

```text
选择或拖拽文件
  → 校验扩展名、文件头、数量和大小
  → 复制到 Electron 临时目录
  → 主进程本地解析
  → 将文本或图片上下文注入模型请求
  → 任务完成后清理临时文件
```

当前边界：单文件最大 20MB，单次最多 5 个附件，单文件文本提取最多 100,000 字符，全部附件合计最多 180,000 字符。Office 文件使用本地解析库处理，解析失败会提示错误，不会破坏其他会话能力。

### 4.4 工具系统

当前内置工具包括：

| 工具                     | 权限    | 用途                            |
| ---------------------- | ----- | ----------------------------- |
| `time_current`         | read  | 获取当前时间。                       |
| `calculator_calculate` | read  | 计算数学表达式，不使用 `eval`。           |
| `file_list`            | read  | 列出项目目录内容。                     |
| `file_read`            | read  | 读取项目目录内文本文件，限制读取长度。           |
| `file_write`           | write | 写入或修改文件。                      |
| `http_fetch`           | read  | 发起受控 HTTP 请求，包含响应大小、重定向和超时限制。 |

工具通过统一的 `ToolDefinition` 注册，并由 `ToolRegistry` 管理列表、查询和模型协议转换。执行器负责参数校验、权限判断、超时、取消、错误码和结果截断。

### 4.5 权限与用户确认

项目提供两种会话权限模式：

- **ask（请求批准，默认）**：read 工具自动执行；write 工具先生成审批卡片，用户批准后执行；dangerous 工具拒绝执行。
- **full（完全访问权限）**：read 工具自动执行；write 工具跳过审批，但仍进行参数和路径校验；dangerous 工具仍然拒绝执行。

`file_write` 的审批预览包含目标路径、操作摘要和内容摘要。审批状态包含 pending、approved、rejected、expired、cancelled 等终态，并保存到 Electron `userData` 目录。刷新页面后，客户端可以重新加载未决审批。

### 4.6 Skill 能力包

Skill 是用户可以手动启用的 Markdown 提示词能力包。它只注入文本规范，不执行脚本、不注册工具，也不能绕过权限审批。

Skill 支持两个来源：

- 全局目录：`<Electron userData>/skills`；
- 项目目录：`<项目目录>/.agent/skills`。

同名项目 Skill 覆盖全局 Skill。Skill 的启用状态按会话保存，用户在 Skills 页面刷新和勾选后，内容会在下一次请求时追加到 Agent 系统提示词中。单个 `SKILL.md` 最大 64KB，单次请求注入的 Skill 正文合计最大 200KB。

### 4.7 MCP 外部工具服务

令旗可以作为 MCP Client，通过本地 `stdio` 方式连接外部 MCP Server。基本流程为：

```text
MCP 页面配置
  → Electron 主进程启动本地 MCP Server
  → 通过 stdio / JSON-RPC 发现 tools
  → 注册到 Agent 工具列表
  → 模型调用 MCP 工具
  → MCP Server 执行并返回结果
```

第一版接入范围为 MCP Tools，不包含 Resources、Prompts 和 Sampling。工具采用 `mcp__服务名__工具名` 命名空间避免冲突，并依据 MCP annotations 映射到现有 read、write、dangerous 权限模型。

MCP 配置保存到 `userData/mcp-servers.json`，不会写入当前项目目录。应用启动时连接启用的服务，服务异常只影响对应服务，不影响内置工具和其他 MCP 服务。

## 五、Agent 任务执行流程

### 5.1 主流程

```text
用户输入自然语言任务
  → 携带会话上下文、附件和启用的 Skill
  → 准备并解析附件
  → 协议适配层构造模型请求
  → 模型返回文本或工具调用
  → 工具执行前进行权限判断
  → 必要时暂停并等待用户审批
  → 执行工具并回填结果
  → 继续下一轮模型决策
  → 输出最终回答
```

核心循环位于 `electron/agentLoop.ts`。当前每次请求最多进行 8 步工具调用循环；最后一步不再携带 tools，强制模型输出最终回答，避免任务无限循环。

### 5.2 任务状态

任务状态定义在 `shared/task.ts`：

```text
queued
  → preparing_attachments
  → parsing_attachments
  → generating
  → waiting_approval
  → running_tool
  → completed / failed / cancelled
```

状态通过 `task-status` IPC 事件同步到前端。失败时界面显示可重试提示；用户停止时，`AbortSignal` 会贯穿模型流和工具执行；停止请求会取消 pending 审批，但已经生成的内容会保留。

### 5.3 错误恢复

- 模型请求错误、工具错误、附件解析错误和审批超时分别反馈。
- 工具执行结果带有结构化错误码和是否可重试标识。
- 失败重试会移除末尾失败占位消息，复用最近一次用户消息。
- 页面刷新后可通过 `list-pending-approvals` 恢复未决审批。
- 应用启动时清理超过 1 小时的孤立附件目录，避免临时文件长期残留。

## 六、技术架构

### 6.1 分层结构

```text
React 渲染进程
  Chat / Message / Sidebar / Settings / ToolList / SkillManager / McpManager
        ↓ contextBridge + IPC
Electron Preload
        ↓ 白名单 API
Electron 主进程
  请求代理 · 协议适配 · SSE 解析 · Agent Loop · 工具执行 · 审批 · 附件 · MCP
        ↓
本地资源与外部服务
  localStorage · userData · 项目目录 · 本地 MCP Server · OpenAI/Anthropic API
```

### 6.2 关键目录与职责

| 目录或文件                     | 职责                            |
| ------------------------- | ----------------------------- |
| `src/components/`         | 聊天、会话、设置、工具、Skill 和 MCP 管理界面。 |
| `src/hooks/useChat.ts`    | 发送消息、接收流式事件、停止、重试和审批事件处理。     |
| `electron/main.ts`        | 窗口创建、IPC 注册、请求调度和生命周期管理。      |
| `electron/agentLoop.ts`   | Agent 工具调用循环和系统提示词拼装。         |
| `electron/protocol.ts`    | OpenAI / Anthropic 请求和流式响应适配。 |
| `electron/tools/`         | 工具定义、注册表、参数校验、执行器和路径安全。       |
| `electron/approvals.ts`   | 审批创建、批准、拒绝、超时、持久化和清理。         |
| `electron/attachments.ts` | 附件复制、本地解析和临时文件清理。             |
| `electron/skills.ts`      | Skill 扫描、解析、覆盖和提示词生成。         |
| `electron/mcp.ts`         | MCP 服务配置、连接、工具发现和生命周期。        |

## 七、安全与治理

### 7.1 密钥与请求安全

- API 请求由主进程直接发出，避免密钥进入渲染进程运行时状态。
- API 配置保存在本地，不上传到项目目录或第三方服务。
- OpenAI 与 Anthropic 协议通过适配层转换，统一由主进程调度。

### 7.2 文件与路径安全

- 文件工具默认限制在关联项目目录内。
- 通过 `pathSecurity.ts` 拒绝 `../` 越界路径。
- 通过真实路径解析拒绝符号链接绕过目录边界。
- `file_read` 限制读取长度，`file_write` 对目标路径和父目录进行校验。
- `full` 模式允许更宽的写入范围，但不会解除危险工具拒绝规则。

### 7.3 工具安全

- `read` 工具无副作用，自动执行。
- `write` 工具可要求人工确认。
- `dangerous` 工具当前不暴露给模型，统一拒绝。
- 执行器提供超时、取消、结果截断和结构化错误反馈。

### 7.4 附件安全

- 限制附件扩展名、文件头、数量、单文件大小和总文本长度。
- 附件先复制到受控临时目录，再由主进程解析。
- 任务结束后清理临时文件，应用启动时清理孤立目录。
- 附件只作为上下文输入，不会自动改变 `file_write` 权限。

## 八、典型使用场景

### 8.1 知识资产问答

读取本地制度、审计资料、项目说明或历史技术资产，快速完成摘要、问答、差异提取和重点标注。

### 8.2 文件整理与审查

将 PDF、DOCX、XLSX、PPTX 等材料交给 Agent，完成表格整理、文档对比、风险点提取和会议材料初稿生成。

### 8.3 研发辅助

关联项目目录后，Agent 可以在路径安全边界内读取源码、测试文件和项目文档，辅助代码审查、文档整理和问题定位。

### 8.4 办公智能助手

通过自然语言完成总结、改写、清单生成、会议纪要和报告初稿，涉及写入文件时保留审批和人工确认环节。

### 8.5 MCP 专业工具接入

将企业内部或本地部署的 MCP Server 接入客户端，为 Agent 增加专业工具，同时复用既有权限和审批机制。

参考 PPT 的演讲节奏，建议按照以下顺序演示：

## 十二、结束语

令旗桌面客户端 Agent 的核心价值，是让大模型从“回答问题”进入“在本地受控地完成工作”。它把对话、文件、工具、MCP、Skill 和人工审批组织成一条完整链路，在保持灵活性的同时，给企业场景提供明确的权限边界、任务状态和安全治理能力。

**用桌面 Agent 连接本地文件、工具与大模型，让每个人都能安全、高效地完成业务工作。**
