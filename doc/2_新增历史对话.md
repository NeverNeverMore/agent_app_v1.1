# 新增历史对话

## 一、功能概述

本次修改为桌面端 Chat 客户端增加了完整的会话历史管理能力，并优化了项目文件夹关联入口。

## 二、会话历史功能

### 1. 会话创建

- 点击左侧“新对话”创建新的空白会话。
- 新会话会自动成为当前活动会话。
- 原有会话内容不会被清空，可以继续从历史列表切换回来。

### 2. 会话切换

- 左侧“会话历史”区域展示所有会话。
- 点击任意历史会话即可切换到对应的消息内容。
- 当前会话会使用高亮样式显示。
- 会话列表按照最近更新时间排序。

### 3. 会话名称

- 新会话默认名称为“新对话”。
- 发送第一条消息后，如果会话仍使用默认名称，会自动使用首条消息生成会话名称。
- 点击会话右侧的铅笔按钮可以修改名称。
- 双击会话名称也可以进入编辑状态。
- 按 `Enter` 保存名称。
- 点击编辑框外部保存名称。
- 按 `Esc` 取消编辑。
- 会话名称不能为空，空名称不会保存。

### 4. 会话删除

- 点击会话右侧的删除按钮发起删除操作。
- 删除前会显示确认对话框。
- 点击“取消”保留会话。
- 点击“删除”后永久删除当前会话及其消息记录。
- 删除最后一个会话后，系统会自动创建一个新的空白会话。

### 5. 本地保存

- 会话列表、消息内容、会话名称和项目文件夹关联信息保存在浏览器本地存储中。
- 应用重新启动后可以恢复之前的会话历史。
- 会话状态使用 `chat-conversations-state` 作为本地存储键。

## 三、项目文件夹关联

- 当前会话可以关联一个项目文件夹。
- “关联项目文件夹”按钮位于消息输入框下方。
- 点击按钮后可以通过系统目录选择窗口选择文件夹。
- 关联成功后，输入框下方显示当前项目文件夹路径。
- 每个会话独立保存自己的项目文件夹关联。
- 切换会话时，项目文件夹显示会同步切换。
- 项目文件夹选择通过 Electron 主进程和 preload IPC 安全桥接实现。

## 四、思考状态计时

- 发送消息后显示“思考中... x秒”。
- 计时从本次请求开始时计算，每秒更新一次。
- 请求完成或停止生成后，计时状态自动结束。
- 点击停止按钮可以中止当前模型请求。

## 五、左侧菜单

左侧菜单包含以下入口：

- 新对话
- 工具
- Skills
- MCP

“工具”“Skills”和“MCP”目前作为功能入口保留，并显示对应的占位页面，方便后续扩展。

## 六、设置抽屉

- 设置面板从窗口右侧以抽屉形式打开。
- 只能点击右上角关闭按钮退出设置抽屉。
- 点击抽屉外部不会关闭设置。
- 设置内容包括：
  - 接口密钥
  - API 请求地址
  - 选用模型
  - 检测联通
- 点击“保存”后设置会保存，但不会自动关闭抽屉。
- 设置数据保存在本地存储中。

### 前端界面

- `src/App.tsx`：应用主布局、会话切换、删除确认和项目文件夹入口。
- `src/components/Sidebar.tsx`：左侧菜单、会话历史、会话重命名和删除操作。
- `src/components/Chat.tsx`：消息区域、输入框、思考计时和项目文件夹按钮。
- `src/components/ConfirmDialog.tsx`：会话删除确认对话框。
- `src/components/Settings.tsx`：右侧设置抽屉和 API 设置功能。
- `src/index.css`：侧边栏、会话列表、输入区、抽屉和确认对话框样式。

### 状态与类型

- `src/hooks/useConversations.ts`：会话创建、切换、重命名、删除、本地持久化和项目文件夹状态管理。
- `src/hooks/useChat.ts`：按会话保存流式消息和请求状态。
- `src/types/chat.ts`：消息、会话和主菜单类型定义。
- `src/types/electron.d.ts`：渲染进程 Electron API 类型声明。

### Electron 桥接

- `electron/main.ts`：增加系统项目文件夹选择处理逻辑。
- `electron/preload.ts`：暴露 `selectFolder` 文件夹选择 API。

## 九、持久化实现

### 1. 存储位置

- 应用运行在 Electron 内置的 Chromium 渲染环境中。
- 会话历史使用 Chromium 提供的 `localStorage` 保存。
- 数据保存在 Electron 应用自己的用户数据目录中，不保存到项目目录。
- 不使用电脑上单独安装的 Chrome、Edge 等外部浏览器的存储空间。
- 如果将 Vite 页面地址复制到外部浏览器中打开，外部浏览器会使用独立的 `localStorage`，与 Electron 应用中的历史记录互不相同。

### 2. 存储键

会话状态使用以下 `localStorage` 键保存：

```text
chat-conversations-state
```

实现文件：

```text
src/hooks/useConversations.ts
```

### 3. 读取流程

应用启动时，`useConversations` 通过 `loadState` 读取 `chat-conversations-state`：

1. 调用 `localStorage.getItem` 获取保存的 JSON 字符串。
2. 使用 `JSON.parse` 解析会话状态。
3. 校验会话列表和当前会话 ID。
4. 恢复会话列表、消息内容、会话名称、项目文件夹和当前选中会话。
5. 如果没有有效数据，则自动创建一个新的“新对话”会话。

### 4. 保存流程

会话状态发生变化后，React 的 `useEffect` 自动执行保存：

1. 会话新建、切换、重命名、删除或消息内容变化时更新 React 状态。
2. `useEffect` 监听完整会话状态。
3. 使用 `JSON.stringify` 将状态转换为 JSON。
4. 调用 `localStorage.setItem` 写回 `chat-conversations-state`。

### 5. 保存的数据

每个会话包含以下字段：

```json
{
  "id": "会话唯一 ID",
  "title": "会话名称",
  "messages": [
    {
      "role": "user",
      "content": "用户消息"
    },
    {
      "role": "assistant",
      "content": "模型回复"
    }
  ],
  "projectFolder": "关联项目文件夹路径",
  "createdAt": 0,
  "updatedAt": 0
}
```

除此之外，整体状态还保存当前选中的会话：

```json
{
  "conversations": [],
  "activeConversationId": "当前会话 ID"
}
```

### 6. 异常处理

- 读取或解析本地数据失败时，应用会回退到新的空白会话。
- 保存失败时不会阻止聊天界面继续运行。
- 删除最后一个会话后，应用会自动创建新的空白会话，保证始终存在可用会话。
- API 接口密钥和模型配置仍由 `useApiConfig` 单独保存在本地，不与会话历史混用。
