参考hermes agent项目

1.工具调用能力:
    聊天chat bot和AI agent第一分界线,就是是否能调用工具
    如:搜索互联网或调内部知识库,读取创建修改本地文件,运行脚本或代码,调用http api,数据库操作,浏览器操作,外部服务集成

2.工具调用权限
    而模型只提出工具调用,是系统去负责执行.涉及权限的问题,最好不要让模型拥有无限制的系统权限
    
3.反馈输出
    chat流式输出,停止,重试和错误恢复

4.上下文管理
    当前上下文限制,上下文压缩,对话摘要,不同会话共享上下文,超长上下文处理,长期记忆等

5.文件和多模态能力
    不仅仅支持纯文本,支持pdf,word,excel,图片上传,图片理解,表格分析等
6.记忆能力
    会话记忆:当前临时记忆
    用户记忆:跨对话有效会话记忆
    项目记忆:项目或工作区记忆
    任务记忆:当前任务的目标、约束和进度


AI反馈 建议的优先级
如果你准备迭代开发，建议按下面顺序推进：
    P0：从聊天应用变成可用 agent
        1.流式输出、停止、重试
        2.统一工具调用框架
        3.工具权限和用户确认
        4.文件上传与文件分析
        5.长上下文压缩
        6.任务状态和错误恢复
        7.API Key、日志、基础安全隔离
    P1：达到主流 agent 的完整体验
        1.浏览器搜索和网页访问
        2.代码执行或数据分析沙箱
        3.用户长期记忆
        4.任务规划和多步骤执行
        5.对话搜索、标签、归档、导出
        6.多模型和多供应商
        7.MCP/插件/技能系统
        8.后台任务和定时任务
    P2：形成平台能力
        1.多用户工作区
        2.团队协作与权限
        3.Agent 模板和自定义 Agent
        4.第三方服务连接器
        5.Agent 间协作
        6.评测平台
        7.成本控制和自动模型路由
        8.插件市场或技能市场

实现 2.统一工具调用框架
    第一版:开发“模型能发现工具 → 调用工具 → 获取结果 → 继续回答”的完整链路
        可以做一些只读工具例如:获取时间,读取文件路径,读取文件内容,计算表达式等
    第一版验收标准:
        1.模型能识别并调用一个内置工具。
        2.工具参数经过 JSON Schema 校验。
        3.工具结果能回传给模型，模型能基于结果生成最终答案。
        4.前端能看到工具调用开始、成功和失败状态。
        5.工具调用能保存到对话历史。
        6.工具执行支持超时和用户停止。
        7.工具不存在、参数错误、执行异常时不会导致整个服务崩溃。
        8.达到最大调用轮数后能安全结束。
        9.工具实现可以独立新增，不需要修改核心对话循环。
        10.后续可以在不改执行引擎的情况下加入权限确认。

    第二版:权限和确认
        如权限完全放开自动执行,写入修改等权限确认,及界面优化
    
    第三版:补齐基础设施
        这些是让 agent 从“能跑”到“稳”的关键，缺任何一个都容易在真实使用中翻车。
        1. 审批持久化与刷新恢复（最高优先）
            - 当前审批只存主进程内存，应用重启后待审批请求全丢，Agent 会一直等到 5 分钟超时。
            - 需要：审批落盘（sqlite 或文件），刷新后恢复 pending 状态，或明确标记为已取消并通知主进程清理。
        2. 符号链接越界修复
            - file_read/file_write 的路径检查只做了字符串前缀判断，项目目录内的符号链接/junction 可绕过边界访问外部文件。
            - 需要：用 realpath 校验最终路径，拒绝越界符号链接。
        3. 自动化测试
            - 目前只有类型检查和构建，没有任何运行时测试。
            - 建议先补工具层测试：参数校验、计算器边界、路径越界、审批批准/拒绝/过期/重复提交、参数哈希篡改、AbortSignal 取消、循环上限。

    第四版:新增 Agent 能力
       基础设施补齐后，顺序扩展能力：
       1. 联网搜索与网页读取
          - 新增 web_search、web_fetch 两个 read 工具，让 Agent 能查实时信息。
          - 注意：需要给模型注入当前时间，否则搜索时效性会出错。
          - 安全：限制返回大小、超时、内容截断。
       2. 文件上传与文件分析
          - 支持用户上传 PDF、Word、Excel、图片、代码文件。
          - 不只是转成纯文本，要保留页码、行号、表格结构等引用信息。
          - 这是从聊天工具变成实用 agent 的重要一步。
       3. 长上下文压缩
          - 当前对话历史无限增长，迟早会超模型上下文限制。
          - 需要：历史消息自动压缩、对话摘要、工具结果截断、重要信息保留。
          - 分层上下文：系统指令 -> 用户偏好 -> 当前任务 -> 最近对话 -> 历史摘要 -> 长期记忆。
       4. 任务状态与错误恢复
          - 多步骤任务的计划展示、步骤状态、失败重试、断线恢复。
          - 这是复杂 agent 闭环的必要组件。
