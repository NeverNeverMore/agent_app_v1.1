# 项目启动说明

本文档介绍如何在 Windows 环境下启动并运行 `四方上行 Chat Client` 开发环境。

## 前置环境

1. 安装 Node.js（建议 18 及以上版本）。
2. 确保 npm 可用。

```powershell
node -v
npm -v
```

## 进入项目目录

```powershell
cd D:\root\codex\workspace\agent_app_v1.1
```

## 安装依赖

```powershell
npm install
```

安装过程会下载 Electron 二进制包。如果因网络或证书问题失败，出现类似 `unable to verify the first certificate` 的错误，可在当前 PowerShell 窗口临时设置环境变量后重试：

```powershell
$env:NODE_OPTIONS='--use-system-ca'
npm install
```

> 该环境变量只对当前窗口生效，安装完成后即可正常执行后续命令。

## 启动开发环境

```powershell
npm run dev
```

执行后：
- Vite 启动开发服务器。
- Electron 自动打开应用窗口。
- 修改 `src/` 或 `electron/` 下代码后，前端页面和主进程代码会热重载。

## 配置与使用

### 首次打开

首次打开后，界面右下角会显示当前选用的模型。此时需要点击右上角“设置”图标进行配置。

### 填写 API 设置

在设置面板中填写：

| 字段 | 说明 | 默认值 |
|------|------|--------|
| 接口密钥 | 你的 API Key | 空 |
| API 请求地址 | 基础 API 地址，不包含 `/chat/completions` | `https://api.kimi.com/coding/v1` |
| 选用模型 | 要调用的模型 ID | `kimi-code-plan` |

### 检测联通

填写完接口密钥和 API 地址后，点击“检测联通”按钮。应用会调用 `${baseUrl}/models` 接口验证连通性：

- 绿色提示：连接成功，并显示可用模型数量。
- 红色提示：显示具体错误信息（如 HTTP 状态码或网络错误）。

> 注意：如果目标 API 没有开放 `/models` 端点，检测联通可能会失败，但 `/chat/completions` 聊天接口仍可能可用。

### 保存并开始对话

点击“保存”关闭设置面板，回到主界面后，在底部输入框输入问题，按 `Enter` 发送，`Shift + Enter` 换行。模型会流式返回答案。

## 常用命令

```powershell
# 启动开发环境
npm run dev

# 类型检查 + 构建生产产物
npm run build

# 仅构建前端（Vite）
node_modules/.bin/vite.cmd build

# 仅 TypeScript 检查
node_modules/.bin/tsc.cmd --noEmit
```

## 构建说明

`npm run build` 会依次执行：
1. `tsc --noEmit`：检查整个项目的 TypeScript 类型。
2. `vite build`：构建前端产物到 `dist/`，同时构建 `electron/main.ts` 和 `electron/preload.ts` 到 `dist-electron/`。
3. 如需打包为安装程序，可继续配置 `electron-builder`。

## 项目配置入口

如需修改默认 API 地址、模型或显示名称，编辑 `shared/config.ts`：

```typescript
export const API_BASE_URL = 'https://api.kimi.com/coding/v1'
export const DEFAULT_MODEL = 'kimi-code-plan'
export const MODEL_SUGGESTIONS = [
  'kimi-code-plan',
  'kimi-k2-0711',
  'moonshot-v1-8k',
  'moonshot-v1-32k',
  'moonshot-v1-128k',
]
```

## 常见问题

### 启动时提示 Electron 未安装或找不到

重新执行安装命令：

```powershell
$env:NODE_OPTIONS='--use-system-ca'
npm install
```

### 检测联通提示 HTTP 401 / 403

检查接口密钥是否填写正确，以及该 Key 是否有调用 `/models` 的权限。

### 对话没有返回

1. 确认设置已保存。
2. 检查 API 地址和模型 ID 是否正确。
3. 查看主进程控制台输出是否有错误日志。

### 设置保存后重启丢失

设置项保存在 `localStorage` 中，如果清除了应用数据或缓存，设置会丢失。对话历史本身不持久化，重启后清空。
## 打包为 Windows 安装程序

项目已集成 `electron-builder`，配置文件为 `electron-builder.yml`。

### 打包命令

```powershell
# 编译前端 + 主进程 + preload
npm run build

# 打包为当前平台安装程序（Windows 下会生成 .exe 安装包）
npm run dist

# 仅打包 Windows 版本
npm run dist:win
```

### 打包产物

打包完成后产物位于 `release/` 目录：

- `release/win-unpacked/`：免安装的绿色版，可直接运行其中的 `四方上行 Chat Client.exe`。
- `release/四方上行 Chat Client Setup 0.1.0.exe`：Windows 安装程序（以管理员身份运行打包命令时才能成功生成）。

### 常见问题

#### 打包时报 winCodeSign 解压失败

Windows 非管理员环境打包安装程序时，`electron-builder` 下载的 `winCodeSign` 包含 macOS 符号链接，7-Zip 无权创建会导致失败：

```text
ERROR: Cannot create symbolic link : 客户端没有所需的特权。
```

解决方案：
1. 以管理员身份打开 PowerShell 或终端，重新执行 `npm run dist:win`。
2. 或开启 Windows 开发者模式（设置 → 隐私和安全性 → 开发者模式 → 打开），然后重新打包。

> 即使安装程序生成失败，`release/win-unpacked/` 下的绿色版 `.exe` 通常已经可用，可以直接运行测试。

#### 设置自定义图标

未配置自定义图标时，`electron-builder` 会使用 Electron 默认图标。正式分发前，建议在 `electron-builder.yml` 中设置 `win.icon` 并准备好 ICO 格式图标文件。

```yaml
win:
  target: nsis
  icon: build/icon.ico
```
